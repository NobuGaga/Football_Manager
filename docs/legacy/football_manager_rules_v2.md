## 一、历史数据汇总

### 1.1 去重规则

- **判定标准**：先以「比赛时间」为准；比赛时间相同，则进一步判断「对阵双方」信息。
- **覆盖逻辑**：对阵双方信息相同即为同一场比赛，**排在下面的数据覆盖上面的数据**（包括结果类型等全部信息）。

### 1.3 排序规则

历史数据输出（CSV）须执行以下排序，确保数据按时间线有序排列：

| 排序优先级 | 排序列 | 排序方向 | 说明 |
|-----------|--------|----------|------|
| 第一优先级 | `比赛时间` | 升序（ASC） | 时间较早的比赛排在列表上方 |
| 第二优先级 | `场次` | 升序（ASC） | 同一时间多场比赛时，按场次序号从小到大排列 |

**排序示例**：
- 周三001（18:30）→ 周三002（18:30）→ 周三003（20:15）→ 周三004（20:15）
- 周六013（21:30）→ 周六014（21:30）→ 周六015（21:30）→ 周六016（21:30）

**实现说明**：
- `比赛时间` 列可能包含两种格式：`YYYY/M/D H:MM`（如 `2026/4/15 2:00`）或 `MM-DD H:MM`（如 `05-10 13:00`）。排序前须统一解析为可比较的日期时间对象，缺失年份的默认按当前数据年份（2026年）补全。
- `场次` 列格式为 `周XNNN`（如 `周三005`），排序时提取末尾三位数字作为排序键。

## 二、预测比分

### 2.1 数据抓取

指令触发词：`预测比分`

- **数据源**：https://m.sporttery.cn/mjc/jsq/zqhhgg/
- 从该网站拉取最新足球比赛数据，使用表格格式汇总展示（原始列名含 `预测比分 (Kimi)`，输出统一为 `预测比分_Kimi`）。

### 2.2 输出格式规范

**不按日期分块**，合并为一个完整表格，按**比赛时间先后顺序**排列。

**表格列（完整版）**：

| 场次 | 联赛 | 对阵 | 比赛时间 | 让球 | 主胜 | 平局 | 主负 | 让球主胜 | 让球平局 | 让球主负 | 预测比分_Kimi | 我的预测 (胜平负) | 我的预测 (比分) | 实际比分 | 结果类型 | AI比分预测结果 | 胜平负预测结果 | 比分预测结果 |
|------|------|------|----------|------|------|------|------|----------|----------|----------|---------------|------------------|----------------|----------|----------|----------------|----------------|--------------|

- `让球` 列格式统一为 `0/让球数`（如 `0/-1`、`0/+1`），表示基准盘口与实际让球盘口的组合。
- `预测比分_Kimi` 列：按照预测可能性从高到低、从左到右排列，**预测三个比分结果**。
- `预测比分_Kimi` 列不用空格缩进，使用 `/` 符号分隔。

### 2.5 比分格式预处理规则

所有比分相关列（`预测比分_Kimi`、`我的预测 (比分)`、`实际比分`）在输出前须执行前导零清理：

- **规则**：比分数字前不得出现无意义的前导 `0`，如 `1:02` → `1:2`、`0:01` → `0:1`、`2:01` → `2:1`。
- **处理范围**：单比分（如 `1:02`）及多比分组合（如 `1:1/1:02/0:01`）均须逐段清理。
- **实现方式**：将冒号两侧的数字转为整数后再拼接，确保输出格式统一为 `主队进球:客队进球`（无前导零）。

### 2.3 AI 盲区补漏策略

1. **平局盲区**
   - 赔率平局 ≤ 3.5 时，必须纳入 `1:1` / `0:0` 为备选。
   - 交锋平局率 > 30% 时，增加 `2:2` 为次选。
   - 挪超 / 日职 / 欧冠 / 葡超等小爆冷高发联赛特别注意平局。
   - **V2新增**：0:0实际出现39次却从未首选预测，次选也极少覆盖，需强制补漏。
   - **V2新增**：2:2实际出现30次但首选仅1次，需增加平局备选覆盖。

2. **主胜大胜扩展**
   - 主胜 < 1.50 且让球 `-1` / `-2` 时：首选 `2:0` / `3:0`，次选 `4:1` / `3:1`。

3. **客胜冷门预警**
   - 客胜 > 4.0 但客队状态不差时，备选加入 `1:2`。

4. **高比分盲区（V2新增）**
   - 3:2实际出现17次、2:3出现14次、4:0出现12次、4:1出现11次，均从未作为首选预测。
   - 在赔率差<0.5或赔率差>5的特殊赔率结构下，次选应覆盖3:2/2:3等高比分。

## 三、预测核对

指令触发词：`预测核对`

- 根据提供的预测核对表数据（图片或表格数据），从 https://m.sporttery.cn/mjc/zqsj/?tab=result 网站获取实际比赛结果数据填入预测核对表内。
- **规则**：不要删除原来预测核对表里的赔率数据（包括主胜/平局/主负、让球主胜/让球平局/让球主负等全部原始赔率列），须**完整保留并输出**。

### 3.1 输出格式规范

按照**预测核对表**标准表格格式输出 Markdown 表格与 CSV 文件，列顺序固定如下：

| 场次 | 联赛 | 对阵 | 比赛时间 | 让球 | 主胜 | 平局 | 主负 | 让球主胜 | 让球平局 | 让球主负 | 预测比分_Kimi | 我的预测 (胜平负) | 我的预测 (比分) | 实际比分 | 结果类型 | AI 比分预测结果 | 胜平负预测结果 | 比分预测结果 |
|------|------|------|----------|------|------|------|------|----------|----------|----------|---------------|------------------|----------------|----------|----------|----------------|----------------|--------------|

- `预测比分_Kimi` 列：不用空格缩进，使用 `/` 符号分隔（如 `2:0/1:0/3:0`）。
- `AI 比分预测结果` 列：使用 emoji 符号 `1️⃣` `2️⃣` `3️⃣` `❌` 填入。
- `结果类型` 列：使用 `🔴大爆冷` / `🟡小爆冷` / `🟢不爆冷` 填入。
- 所有原始赔率列、用户预测列须完整保留，不得删除或隐藏。

### 3.2 用户预测核对规则

`胜平负预测结果` 与 `比分预测结果` 两列用于核对用户自主预测是否命中，规则如下：

- **数据来源**：
  - `胜平负预测结果` ← 比对 `我的预测 (胜平负)` 与 `实际比分` 推导出的实际胜平负。
  - `比分预测结果` ← 比对 `我的预测 (比分)` 与 `实际比分`。

- **判定标准**：
  - `我的预测 (胜平负)` 填写内容为 `主胜` / `平局` / `主负`（或简写 `胜` / `平` / `负`）。
  - `我的预测 (比分)` 可填写单个或多个比分，多比分使用 `/` 分隔。

- **输出格式**：
  - 命中填 `✅`，未命中填 `❌`。
  - **不附加任何文字说明**，仅保留 emoji 符号。
  - 若用户未提供对应预测（该列为空），则结果列保持空白，不填 `✅` 也不填 `❌`。

- **比分比对前须执行前导零清理**，确保 `1:02` 与 `1:2` 视为同一比分。

## 四、判断规则

### 4.1 结果类型 Emoji 标识

- 🔴 **大爆冷**：最大赔率结果
- 🟡 **小爆冷**：第二大赔率结果
- 🟢 **不爆冷**：最小赔率结果

### 4.2 正常赔率缺失时的判定

- 当正常胜平负赔率（主胜 / 平局 / 主负）缺失为 `--` 时，使用让球赔率（让球主胜 / 让球平局 / 让球主负）判断结果类型。
- 结果类型**不添加 `(让)` 后缀**，保持原格式（🔴大爆冷 / 🟡小爆冷 / 🟢不爆冷）。

### 4.3 让球判断规则

让球 `(-n)` 时，计算让球后比分 = `(主队进球 - n) : 客队进球`。

| 让球数 | 判定标准 | 结果 |
|--------|----------|------|
| 让 `-2` 球 | 净胜 ≥ 3 球 | 让胜 |
| 让 `-2` 球 | 净胜 = 2 球 | 让平（走水） |
| 让 `-2` 球 | 净胜 ≤ 1 球 / 平 / 负 | 让负 |

**参考案例**：让 2 球，实际比分 `2:1`，让球后 `0:1`，对应让负（最小赔率 2.23，不爆冷）。

## 七、策略校验与更新 ← V2新增

指令触发词：`策略校验更新`

当触发该指令时，执行以下完整流程，基于已完结历史数据（CSV）对现有策略文件（`football_manager_policy_full.md`）进行全量校验、校准与新策略挖掘。

### 7.1 执行流程

```
Step 1: 加载数据
  ├─ 读取 足球预测历史数据.csv
  ├─ 解析所有列（赔率、比分、时间、让球等）
  └─ 数据清洗（前导零、缺失值、格式统一）

Step 2: 基础统计校验
  ├─ 总场次、命中场次、命中率
  ├─ 结果类型分布（不爆冷/小爆冷/大爆冷）
  ├─ 预测位置命中分布（1号/2号/3号）
  └─ 与策略文件声明值对比，标记差异

Step 3: 高价值场景校验
  ├─ 逐一验证策略文件中"高价值投注场景"表格
  ├─ 计算实际命中率 vs 声明命中率
  ├─ 样本量变化追踪（如530→545场）
  └─ 标记命中率偏差>5%或样本量<10场的场景

Step 4: 避雷场景校验
  ├─ 逐一验证策略文件中"避雷场景"表格
  ├─ 确认命中率是否仍<20%
  └─ 发现新的低命中率场景（<15%）并记录

Step 5: 联赛策略校验
  ├─ 按联赛分组计算命中率、爆冷率、场均进球
  ├─ 与策略文件"联赛策略卡片"对比
  └─ 标记联赛排名变化或命中率大幅波动（>5%）

Step 6: 赔率/赔率差/时间段/让球策略校验
  ├─ 赔率区间命中率
  ├─ 赔率差区间命中率
  ├─ 时间段命中率
  ├─ 让球盘胜率/让平率/让负率
  └─ 与策略文件声明值对比校准

Step 7: 评分模型校验
  ├─ 按评分规则重新计算所有场次评分
  ├─ 评分区间命中率分布
  ├─ 评分>8+赔率<2.5组合命中率
  └─ 评分模型参数是否需要调整

Step 8: 新策略挖掘
  ├─ 遍历所有可能的条件组合（联赛×比分×赔率×时间×让球）
  ├─ 筛选命中率>40%且样本>=5场的组合
  ├─ 筛选命中率>35%且样本>=10场的组合
  ├─ 排除与现有策略重复的场景
  ├─ 按命中率降序排列候选新策略
  └─ 人工判断新策略的逻辑合理性

Step 9: 偏态套利策略校验
  ├─ 按联赛计算结果类型偏态分布
  ├─ 计算各方向EV比（2,3关/3,4关/4,5关）
  ├─ 与策略文件EV表对比校准
  └─ 发现新的高EV偏态场景（EV比>2.0）

Step 10: AI盲区分析更新
  ├─ 实际比分TOP15 vs 首选预测覆盖
  ├─ 从未首选预测但实际出现>=3次的比分
  ├─ 首选预测过度/不足的比分
  └─ 更新"AI盲区改进建议"

Step 11: 生成更新策略文件
  ├─ 汇总所有校验结果与校准数据
  ├─ 整合新发现的高价值策略
  ├─ 更新版本号（如V3→V4）
  ├─ 撰写变更日志
  └─ 输出为 football_manager_policy_full.md

Step 12: 生成校验报告
  ├─ 列出所有校验通过的项（✅）
  ├─ 列出所有需要校准的项（⚠️）
  ├─ 列出所有新发现的策略（🆕）
  └─ 输出为 Markdown 格式报告
```

### 7.2 校验判定标准

| 校验项 | 通过标准 | 校准标准 | 新增标准 |
|--------|----------|----------|----------|
| 高价值场景命中率 | 实际与声明偏差≤5% | 偏差>5%时更新声明值 | 命中率>40%且样本>=5场 |
| 避雷场景命中率 | 实际仍<20% | 实际≥20%时移出避雷 | 实际<15%且样本>=10场 |
| 联赛命中率 | 实际与声明偏差≤5% | 偏差>5%时更新 | 新联赛样本>=5场 |
| 评分区间命中率 | 实际与声明偏差≤5% | 偏差>5%时更新 | 评分模型参数优化 |

### 7.3 新策略纳入标准

新策略必须同时满足以下条件方可纳入策略文件：

1. **命中率门槛**：命中率 ≥ 40%（样本<10场）或 ≥ 35%（样本≥10场）
2. **样本量门槛**：样本 ≥ 5场（必投/重点策略）或 ≥ 10场（可选策略）
3. **逻辑合理性**：策略必须有明确的足球逻辑解释（如"西甲平局率高"、"上午场次冷门少"）
4. **非冗余性**：新策略不得与现有策略完全重叠（如"首选1:1+西甲"与"首选1:1"是不同策略）
5. **稳定性**：该策略在历史数据的前半段和后半段命中率差异 ≤ 10%
6. **可执行性**：策略条件必须可在实际投注前明确判断（如"赔率<1.5"可判断，"球队士气高"不可判断）

### 7.4 策略文件更新规范

更新 `football_manager_policy_full.md` 时须遵循：

1. **版本号递增**：如 V3 → V4 → V5
2. **变更日志**：在文件末尾添加变更日志表格，记录每个章节的变更内容、原因
3. **数据标注**：所有命中率、样本数须标注数据来源（"基于545场"）
4. **保留历史**：不删除旧策略，仅标记"（V4校准）"或"（V4新增）"
5. **高亮新增**：新策略在表格中使用 **粗体** 标注命中率
6. **风险提示**：样本<15场的策略须标注"（样本少但极高价值）"

### 7.5 输出格式

触发 `策略校验更新` 指令后，依次输出：

1. **校验摘要**：总场次、校验项数、通过项数、校准项数、新增项数
2. **详细校验表**：按章节列出每个策略的声明值、实际值、偏差、判定结果
3. **新策略候选表**：命中率降序排列，含条件、命中率、样本、逻辑解释
4. **更新后的策略文件**：完整的 `football_manager_policy_full.md` 内容
5. **变更日志**：版本升级说明

### 8.4 评分计算标准（引用策略文件）

评分采用策略文件 V4 评分模型，具体规则如下：

```
基础分0

  韩职/瑞超/荷甲-0.5, 芬超/葡超/英冠-1.5, 德乙-1
```

### 8.5 补漏规则

- 首选 `1:1` 时，次选必带 `0:0`（0:0实际出现39次从未首选预测）。
- 交锋平局率>30% 时，次选增加 `2:2`。
- 让球 `-2` 时，备选加入 `4:0` / `4:1`。
- 首选 `2:1` 时，效率仅27.6%，降权处理并备选加入 `3:2`。
- 主胜<1.50 且让球 `-1`/`-2` 时：首选 `2:0`/`3:0`，次选 `4:1`/`3:1`。

### 8.6 输出约束

1. **仅基于给定数据**：分析严格限于提供的预测比分表场次，不额外补充未列出的比赛。
2. **引用策略文件**：每条建议须标注对应的策略文件章节（如"策略文件二.1"、"策略文件四"）。
3. **保留原始数据**：输出中须完整保留预测比分表的所有原始列（场次、联赛、对阵、赔率、预测比分等）。
4. **风险提示必写**：每场建议必须包含风险提示项，说明该场次的不确定性因素。
5. **冷静声明**：文末附加固定提醒——"以上策略基于历史数据概率计算，足球比赛存在不确定性，请理性投注。"
